## 1. Layer A 时间窗实测（FR-9.4「< 1 s」假设验证）

| 探测项 | 实测耗时 | 样本 |
|---|---|---|
| 网卡 + 地址枚举（含 MTU/状态） | **median 29.0 ms / p95 30.2 ms / max 50.4 ms** | n=30 |
| MTU 读取（独立计时） | <0.01 ms | n=30 |
| UDP 53 出站（DNS 至 223.5.5.5） | **77 ms**（通） | 单发 |
| STUN 3478 探测 ×4 服务（miwifi/bilibili/qq/ekiga） | 全部超时（各 2 s timeout） | 各 1–10 发 |

## 2. 标定结论（参数定案值）

1. **FR-9.4「< 1 s」成立，但有边界条件**：串行实现下 枚举(50) + UDP(≤300) + STUN(≤300) ≈ 0.65 s ✅——前提是**单点探测超时 ≤ 300 ms**。若以 2 s 默认值串行探测多个 STUN，总窗必破 1 s。
2. **探测超时标定值 = 300 ms**：依据本机 DNS UDP RTT 77 ms 的约 4× 余量；局域网/近端 STUN（自建境内）预期 RTT 更低，300 ms 足够覆盖。
3. **多 STUN 必须并行**：RFC 5780 分型需 ≥2 台 STUN，串行则 2×300 ms 探测窗叠加其余项逼近 1 s 上限——并行后总窗 ≈ max(各项) ≈ 0.35 s。
4. **「UDP 出站能力」检测必须分层**：本机实证 UDP 53 通而 3478 全不通——「UDP 通/不通」不是二值。标定为三级探测：UDP 53（基础出站）→ STUN 3478（NAT 画像可用性）→ 业务端口段（打洞可用性）。
5. **STUN 不可达时的降级语义**：本机四个公共 STUN 全不可达（2026 年国内公共 STUN 可用性存疑）——Layer A 报告应输出「NAT 类型：未知（STUN 不可达）」而非检测失败；这反向验证了 SRS「自建 STUN」决策的必要性（§4.6/M1）。

## 3. 本机画像顺带发现（入 link_checks 先验库）

- 12 个 IPv4 地址：真实 LAN 仅 192.168.31.50，其余为虚拟网卡（172.17/172.31）与链路本地（169.254×8）——地址枚举必须过滤虚拟/链路本地接口，否则候选列表被稀释（与 AC-26 幽灵过滤同族问题，IPv4 侧同样存在）；
- IPv6 仅有协议栈无全局地址（S1 冒烟一致）。
