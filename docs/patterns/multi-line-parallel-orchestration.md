# 多线并行编排模式（multi-line parallel orchestration）v0.2 草案

> 状态：**草案，首轮实证已回填至时点②.5**（2026-09-25：AeroFold UI 线 4/4 收口、交付 tag `aerofold-ui/u04-delivery`；汇合单元 U-M2-08 未至）。设计已过 deep-probe 双轨审定（2026-09-24，挑战者信息隔离独立生成 + 对照表），首轮实证 = AeroFold 双线（实例化参数见 [启动包](../plans/2026-09-24-aerofold-dual-track-startup.md)）。
> 晋升触发器（维持）：AeroFold 汇合单元 U-M2-08 完成（时点③）后按实证终判；机制件被证为稳定必需品 → 升入 program-forge skill 本体。已先行落地一项：程序级 resume note 随 B3-handoff 实证决策入 program-forge 0.1.1（K22）+ handoff-inject hook 扩展，见 §9.2。

适用域：campaign 工件区内的工程，因串行执行成为墙钟瓶颈，需要将一条可独立推进的开发线从在途程序中抽出，由第二个 ZCode session 并行编排，后期汇合。

## 1. 启用判据（全满足才启动；任一不满足 = 不启动或先补课）

| # | 判据 | 判据背后的失败形状 |
|---|---|---|
| C1 | 瓶颈归因 = agent 串行执行主导（程序账本实测单元墙钟支持），非用户裁定带宽主导 | 为并行而并行、墙钟无净收益 |
| C2 | 存在可硬切的组件边界：第二线写全新/独立组件，与在途线零写交集（读权互通） | 组件所有权交叉 → 合并地狱 |
| C3 | 第二线输入契约已冻结，或可固化快照（契约出仓有权威源） | Mock 与真契约漂移失控 |
| C4 | 汇合点可定义、可预置进双侧 DAG | 汇合变事后硬拼 |
| C5 | 用户接受 ≈2 倍 token/算力消耗换墙钟 | 价值排序倒挂 |

**反信号（命中即不建议启动）**：单线单元墙钟普遍 < 2h（启动开销吞掉收益）；组件边界切不开；契约高频修订且无法快照；用户裁定带宽已是瓶颈；在途线自身处于高危调试中段（注意力被两线撕扯）。

## 2. 不可妥协项（四条，任一方案必须逐条对应构件）

1. **campaign 状态完整性**——两线 `.campaign/` 必须**物理上不可能互写**（「写不到」，非「约定不写」）。
2. **组件所有权硬切**——写权单线独占，读权全互通，git 分支边界为所有权背书。
3. **汇合点预置**——汇合单元在**双侧** DAG 中预先占位，外部门 = 二线交付 tag。
4. **在途线节奏零打扰**——二线的一切需求（契约、约定、裁定）异步化，不打断在途线单元。

## 3. 机制构件（七件；「出处」= 首例实证锚点）

| # | 构件 | 内容 | 出处 |
|---|---|---|---|

| M6 | 中期条件触发触点 | 在途线关键单元合 main 后，二线 rebase 并跑握手级 smoke（optional-conditional，不阻塞在途线）——汇合不能是首次真接触。**窗口条件（首轮实证补）**：二线总寿命 < 在途线 1–2 个单元墙钟时触点大概率无窗口（AeroFold UI 线 4.6h vs 主线单元 10h+，评估纪律正确执行但条件未成真）；此时汇合单元的真链路集成权重应上调 | AeroFold U-M2-03 合 main 为触发；首轮未触发（U-UI-03 实测 origin/main 未含 U-M2-03） |

## 4. 启动协议（六步）

1. **双轨方案确认**（deep-probe：主轨 + 挑战者信息隔离独立生成 → 对照表 → 方案确认停止点）；
2. **启动裁定包一次批准**（含前提清单交付）；
3. **在途线侧写操作**（契约出仓 + ADR 补记 + 在途程序 DAG 追加汇合单元）——归在途线 session 在**单元边界**执行，写权决定不可外派，勿污染在途单元分支；
4. **第二 worktree + 第二 session 启动**（session 启动目录 = worktree 根，全程锁定）；
5. **二线程序锻造**（既有 program-forge 流程；**最小剂量**——轻单元、轻门，不照搬在途线重型单元规格）；
6. **运行纪律**：CONVENTIONS.md 只读（rebase 吸收在途线更新；二线约定需求记单元 brief，汇合时统一回流——绕开 30 行硬顶争抢与双写）；漂移只写 DRIFT-LOG；跨线需求一律挂起等汇合，不私拉通道。**在途回流截止（首轮实证补）**：契约快照含在途标注段时，在途线须在在途单元收账后**下一单元开工前**更新契约文件并关闭 DRIFT 对应行——AeroFold 首轮 U-M2-03 收账后未回流（DRIFT 行 open 至复盘日），二线 Mock 对齐目标持续过期，此债务全部转嫁汇合单元。

## 5. 汇合协议

- 触发 = 在途线收口单元过门 ∧ 二线交付 tag 就绪。
- 汇合单元内容 = Mock 假设清算 + 契约 delta 吸收 + 真链路集成 + **二线 `.campaign/` 归档回主树**（账本单源视图恢复——物理隔离的代价在此补偿）。
- 回并条件：引擎 v2 若放开 parallel（现 `program.py` validate 硬拒 `parallel != "-"`），双程序可无损回并。

## 6. 已知代价与边界

- 跨程序无统一账本视图（物理隔离的直接代价；运行期靠 git log + 双 handoff 轻量人工对账）；
- 第二 worktree 构建缓存双份（磁盘开销；二线以 Web 构建为主可缓解）；
- 契约快照含在途段时须显式标注（「以在途线后续更新为准」），在途线收账后负有更新契约文件的义务；
- 二线 token ≈ 单线两倍；启动开销 = 一次契约快照 + 一次轻量程序锻造 + 一次裁定包，应显著小于被抽出的串行墙钟（C1 保证）。

## 9. 实证采集协议与首轮回填（v0.1 → v1 的证据管线）

**观察原则**：不靠任何 session 的持续记忆（跨 session 无状态），全部证据走工件沉淀 + 触发式复盘（同构于 campaign D1：读状态不读记忆）。观察者 = 复盘时点召唤的 fresh 分析会话，输入 = 下列工件。

| 待验证问题 | 证据落点（天然产物，零额外成本） | 支撑的决策 |
|---|---|---|
| 物理隔离是否零撞车 | 两线各自 `handoff.md` 的摩擦记录 + 双账本完整性 | B1/B3 是否启动 |
| Mock 对账门是否在日常拦截漂移 | 二线各单元门证据（对账输出与拦截次数） | M3 构件保留/加固 |
| 契约漂移频率与方向 | `docs/api/DRIFT-LOG.md` 累计条目 | M2 出仓粒度与更新纪律 |
| 中期 smoke 是否提前暴露集成问题 | 二线中期触点单元证据 | M6 构件去留 |
| 程序内并行排队损失（eligible 却排队时长） | 在途程序账本 unit_start/end 时间戳（脚本后算） | B2（parallel 语义）ROI |
| 汇合成本总量 | 汇合单元 result/evidence：Mock 假设清算条目数、契约 delta 吸收条目数、集成返工量 | 模式文修订 + 双线 ROI 总账 |
| 用户裁定带宽体感 | 用户在复盘时一句话回顾 | M5 裁定包预算化调整 |

**增量约定（一行级）**：两线各 session 在单元 result 的 ruling 行或 handoff 记录「双线摩擦」一行（撞车险情 / 等待 / 参照系困惑），无则免记——随启动包与程序锻造传递。

**复盘时点（工程事件触发，非日历触发）**：①二线 Mock 对账门首个单元过门（Mock 机制首战战报）；②中期 smoke 完成后；③汇合单元完成（终局）。执行方式 = 用户在该时点召唤 fresh 分析会话；产出按三级回写纪律分流：项目级 → 工程 `docs/learnings/`；平台级 → 本模式文修订 + campaign 插件 B 批（B1 显式工程根 / B2 parallel 语义 / B3 分件）改与不改的实证决策；流程级 → 若机制被证为稳定必需品，升入 program-forge skill 本体并升版本号。
