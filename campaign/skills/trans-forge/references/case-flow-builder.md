## 三、9 条反模式教训

| 反模式 | 案例表现 | 处置建议 |
|---|---|---|
| 1. §0 三路混投（最重） | 同一 `##` 节内并存术语表（→SRS）、D0–D10 决策注册表（→adr/）、spec 待评审决策（→DECISIONS 边界）、需求复述（→SRS） | 收编器须按 `###` 子节甚至表级分拆 |
| 2. P 前缀撞车 | 问题清单前缀 `P`（P1–P14）与 `P0`（优先级）/`P95`（NFR 分位数）/`P256`（ECDSA 曲线）正则互污染 | 单字母 P 前缀是 ID 体系最大机器可读性风险，禁入白名单 |
| 3. 通配引用入正文 | as-of spec 1514 行版 L162 出现 `FR-3.x`、L1211 出现 `NFR-5.x` 非完整 ID；聚合引用「FR-3 全组」等 8 处机器需展开 | 正文禁通配，组引用改用「FR-3 全组」注记形态 |
| 4. R 表乱序 | R1,R2,R3,R4,R8,R5,R6,R7（as-of spec 1514 行版 L1393 自注保留源方案乱序）——表格序≠编号序 | 收编 risks.md 时按号排序 |
| 5. TODO 同义异名 | `TODO-推理线程`（as-of spec 1514 行版 L1475）vs `TODO-推理内存`（FR-6.7）同指一值；斜杠复合 token（`TODO-端口段/TODO-网络分段`，L1420/1423/1431）一 token 内嵌两主题 | TODO token 一处值一 token，禁斜杠复合，禁同义异名 |
| 6. file:line 路径前缀不统一 | 正文短路径（`tenancy.py:82-83`）vs 附录 B 全路径（`server_app/tenancy.py:82-83`） | 统一使用相对工程根的全路径 |
| 7. 同文件行号区间两说 | `mqtt_bridge.py:31-106`（附录 B as-of spec 1514 行版 L1491）vs `mqtt_bridge.py:31-206`（§6.6 标题 L1159）——收编时无法判断权威 | 引用前必须实测并给出单一真源区间 |
| 8. FR 内容重复 | FR-8.8 与 FR-7.7 同一改造（as-of spec 1514 行版 L336 自注交叉）——按「一节一需求」解析会重复收录 | 重复条目应标记 deprecated 或合并，稳定编号不删号 |
| 9. 待决项重复登记 | 附录 A 的 `TODO-开通时限` 等值与 §10 D 表、行内 TODO 多处重复 | 待决项只在一个登记点（§10 D 表或 DECISIONS.md）出现 |
