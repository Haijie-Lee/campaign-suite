# pipeline-cases.md — 流水线驱动判例库

campaign 流水线驱动模式的实战判例库。判例只在情境匹配时检索参考，不作执行清单。与 campaign SKILL.md「判例回流」节五步指针同源——词表只存本件，SKILL.md 不复制。

## 判例格式（五要素）

每条判例 = **情境 → 错误 → 机制 → 规则 → 失效条件**。失效条件是灵魂——没有失效条件的经验是教条。

## 判例回流五步

1. **触发信号**——四类必记：**①跳过前提被证伪 ②就绪条件反复不满足 ③charter 误判致复量 ④折叠三条件误用致停点漏停**；失败判例权重高于成功（不对称写入）。
2. **即时登记**——高密度轮次当场标记候选（一句话草稿即可），会话收尾前成文；禁止事后凭记忆重建（遗漏集中在最密的轮次）。
3. **成文**——按五要素格式，失效条件必填。
4. **分辨率裁决**——写入前先检索既有判例：情境与机制同构 → 合并（补充情境或收紧失效条件）；机制不同 → 新条目。库膨胀成复读 = 沉淀失败。
5. **压缩与复活**——库超 ~20 条做压缩：合并进 campaign SKILL.md 判例节、全文备份留血统；每条标注最后验证时间，长期未验证者降权。

无沉淀的使用是浪费。

## 判例

### 1. 分诊后断链：program 首命中短路全链路（2026-09-27，种子判例）

- **情境**：用户布置多流水线编排任务（专利申请案：交底书→检索→申请→OA 四环），消息含「编排」一词；campaign 分诊顺序仲裁中 program 信号首命中，直接路由 program-forge。
- **错误**：program-forge 起手建 DAG 干活，前面的需求对齐与 spec 环节完全跳过，后续 forge 也未按序接力——全链路被首命中短路，用户预期「彼此咬合的流水线」落空。
- **机制**：入口仲裁序与流水线序方向相反且执行用错序（program 首命中短路）；路由器单发无接力角色（「本 skill 动作结束」明文）；forge 间咬合的是工件不是控制流；program-forge 缺上游就绪门。
- **规则**：多环任务（≥2 forge 或含 program 环）进流水线驱动模式——先对齐（Step 1.6）、立 charter（Step 1.7）、按产物状态回路接力推进（Step 2）；program 环不得跳过上游就绪门直接立项。
- **失效条件**：单环任务（纯 SRS 生产、纯文档收编、单 plan 执行）不适用本规则——强行进流水线模式 = 过度仪式化；任务边界在分诊时已明确单环且用户授权直达时，首命中短路是正确行为。
- **证据**：2026-09-27 用户专利案截图实证（本批缘起）；最后验证 2026-09-28。
