# Spec Forge — 检查清单（按需读取）

仅在进入对应工序时读对应节。这里是对抗审查的**视角细目**；机制（双声部、
共识表、裁定分类、审计追踪、收敛循环、准出闸口）在 plan-review-ritual 与
plan-forge 工序 3/3.5，此处不重复。

## 工序 2 — 制坯检查清单

初稿完成后逐条过，每条发现必须引用原文；零发现项也要留「查了什么」一句。

### 需求歧义 lint（离线复跑，与 spec-lint hook 同源三规则）

- [ ] **L1 歧义词**：全文搜 `适当|尽量|必要时|按需|尽快|优化|友好`——每处
     命中给出可验证的量化口径或删除（「优化」对「最优化/优化器」的子串误伤
     = 已知边界，人工裁定）
- [ ] **L2 引用完整**：行内 ID 引用（FR-/NFR-/R/D/C/Q/AC- 词法）在
     graph.json 节点集中存在；图缺失 → 整体跳过并记一行
- [ ] **L3 NFR 数值**：NFR 定义行（表行或 `NFR-x.y：`形态）剔除 NFR 编号
     本身数字后行内无其他数字 → 补量词与阈值

### 两态标记自检

- [ ] 新增/变更范围内，数值断言行未标记清单为空：
     `grep -nE '[0-9]+(\.[0-9]+)?[ ]*(%|ms|s|GB|MB|KB|万|倍|行)' <目标> | grep -vE '【(证据|假设·验证=)'`
- [ ] 标记形逐字：`【证据】` / `【假设·验证=<方法>】`（行尾）
- [ ] 假设条目全部进 evidence-register（表头：
     `| 断言 | 源位置 | 态(证据/假设) | 验证方法 |`），待审计队列不断链

### ID 与结构

- [ ] 新 ID 与既有注册表无冲突（doc_graph 重建后 duplicates 不增）
- [ ] 九节结构完整（模板节未删；找不到内容填 N/A）
- [ ] FR/NFR 每条：单一解释 + 可检验判据 + 测量条件

## 工序 3 — 锻打五视角清单（轮 1 注入 plan-review-ritual 的 CHECKLIST）

通用纪律：只报运行时会炸或执行会卡的问题；引用原文行，引不到的不报；
风格/组织问题不报；零发现视角必须留「查了什么、为什么没有」。

### 视角 1：歧义性

- 逃逸词扫描（L1 词表 7 词）每处命中已展开为量化口径或删除
- 代词（其/该/此/这）每个有唯一先行词；缩略语在术语节已定义
- 每条 FR 单一解释：读两遍能读出两个意思的行 = 命中（一义多读猎手）
- 「等」字列举煞尾：封闭列举还是开放举例，语义边界人工裁定（不加回词表）

### 视角 2：可验证性

- 每条 FR/NFR 有第三方可检验判据（数值阈值或可观测行为）
- 弱判据词（快速/可靠/高效/稳定/易用，无量化）全灭
- 判据含测量条件（何时/何环境/何方法）
- 验收锚（AC 或 NFR 阈值）可被机械引用（有 ID 可指）

### 视角 3：一致性

- ID 引用无悬空（L2 离线复跑）
- 术语全文单一写法（同一概念只用一词）
- 与前序版本及已确认 C 决策无矛盾
- 版本留痕与正文一致：版本行摘要说的改动 = diff 实际改动

### 视角 4：完备性

- 修订触发项（Q 表/CONTEXT）每个点有落点（逐条编号对照，落点引用原文）
- 反向镀金：改了触发项没要求的东西（多出的功能面/外发面）
- 边界与失效模式有定义（输入越界/路径失败时系统的行为）
- 新增 ID 与既有注册表无冲突（doc_graph duplicates 不增）

### 视角 5：可行性

- 技术断言有证据（【证据】）或标假设（【假设·验证=…】）——两态全覆
- 资源/工期断言有出处（实测值带日期，或引真实文档）
- 平台/协议事实可核（引真实文档；核不了的标 [待验证] 进 Q 表）

## 工序 4 — 理解性彩排清单

### 派遣 prompt 骨架（填槽 {DELTA_PATH}）

```
You are a fresh reader with ZERO context. You did not write this SRS delta.
INPUT: {DELTA_PATH}（only this — no repo access, no other files）
For EACH new/changed FR (or quantitative assertion), restate in your own words:
1. 我会如何实现它（implementation sketch）；
2. 我会如何验证它（acceptance test sketch）.
Then report three kinds of points:
- 歧义点：两种以上合理解读的行（引用该行）；
- 不可验证点：无法设计第三方检验的条目（引用该行）；
- 看不懂的术语或引用。
Rules: read-only; quote the exact line for every point; 零发现也合法，
但每条 FR 的复述不许跳过。
```

### 回收检查（编排者逐条）

- [ ] 每条新增/变更 FR 都被复述（无遗漏——漏复述 = 漏测）
- [ ] 歧义点与不可验证点全部回工序 2 补全（不是嘴上答「显然」）
- [ ] 补全后复检：同一 fresh reader 对修订行重述，无新歧义
